# Community chat/forum

Closed community chat for ועד קמ"ד ישיבת חברון (~300 members), UI in Hebrew (RTL), styled after Google Chat.
It is a CHAT, not a forum: the home screen is the main room (live, flat chat). Members open small topic
rooms (table `channels`, one row has is_main). Plus 1:1 DMs and anonymous posting. Member info (profile
card with reputation, DM / anonymous DM buttons) opens only when clicking a name or avatar.
Audience is male yeshiva students only: all UI text is masculine Hebrew (no "חבר/ה"-style slashes), and the
emoji set in `src/lib/emoji.ts` is curated for that audience (no immodest/romantic/alcohol/non-kosher items).

## Architecture
- Frontend: React 19 + Vite + TypeScript, `HashRouter` (GitHub Pages friendly), no UI library; styles in `src/styles.css` (Material 3 tokens, auto dark mode, responsive at 900px).
- Icons: inline SVG Material Symbols. Names listed in `src/components/Icon.tsx`; path data generated into `src/components/iconPaths.ts` from the npm package `@material-symbols/svg-400` (outlined, `<name>.svg` / `<name>-fill.svg`; `push_pin` is `keep`). No icon font, no emoji in UI.
- Main room banner image: `public/hero.jpg` (falls back to a gradient if missing).
- Shared chat UI: `components/ChatStream.tsx` (Google Chat style bubbles: mine on the left in blue, hover toolbar with quick reactions / emoji picker / quote-reply / ⋮ menu), `components/Composer.tsx` (mentions, emoji, photo/video attach + paste, anonymous toggle, typing pings), `lib/useTyping.ts` (broadcast, never carries a name for anonymous writers).
- Polls: `pages/PollsPage.tsx` (/polls list, /polls/:id answer + results). `create_poll` also posts an announcement message (`messages.poll_id`, immutable) in the chosen room; ChatStream shows a button to the poll. Votes are private (`poll_votes` visible only to the voter; totals via `poll_results`).
- Contact the management: `pages/ContactPage.tsx` (/contact) + admin tab "פניות" (`components/FeedbackAdmin.tsx`); table `feedback` written via `send_feedback` (rate-limited); each request is a conversation (`feedback_messages`, `feedback_post` by its author or admins, `components/FeedbackThread.tsx`); `reply_feedback` sets done/open. The contact page lists only MY requests (admins can read all). Admins get a sidebar badge (`open_feedback_count`), email and push for new requests and replies.
- `docs/project-summary.md`: Hebrew summary of the site to paste into AI tools; keep it current when adding features.
- Hebrew birthdays: SQL Hebrew calendar (`hebrew_date()`, verified day-by-day against Intl for 1900-2100), private `birthdays` table, `post_birthdays()` posts a `messages.system` greeting in the main room once per Hebrew year (called on app load and by the email job). Settings: `components/BirthdaySettings.tsx`.
- Nicknames: `nicknames` / `nickname_votes`, functions only (`propose_nickname`, `toggle_nickname_vote`, `remove_nickname`, `nickname_list`); proposers are never exposed. UI: `components/Nicknames.tsx` on the profile.
- Email notifications: `email_prefs` (per member, `components/EmailSettings.tsx`) + `email_queue` filled by triggers (room messages via a deferred constraint trigger so anonymous authors are known; DMs; feedback replies; nicknames). Edge Function `supabase/functions/send-emails` (Gmail SMTP 465, secrets GMAIL_USER / GMAIL_APP_PASSWORD) takes due emails via `email_batch()` (service_role only; frequency, delay, quiet hours, Shabbat, daily cap, only-unread, never the owner's fake inbox) and acks with `email_done()`. pg_cron schedule in `supabase/email-setup.sql`. Never name an anonymous sender in an email. The owner's email is auto-confirmed (`confirm_owner_email` trigger). Sign-up requires email confirmation (Supabase "Confirm email" on): `AuthPage` offers "send again" (`auth.resend`) and, when the confirmation link is opened in another browser (PKCE can't finish there), tells the member the address is confirmed and to log in.
- Fun but professional: "מבזק השבוע" strip inside the main room's blue banner (the banner folds to one slim line via its arrow button, remembered per browser, which also hides the highlights and countdown) (`components/Highlights.tsx`, `weekly_highlights()` = top image and top quote of 7 days by likes x2 + reactions); news-flash maker (`components/GagMaker.tsx`, canvas templates -> image -> `send_gag()`, server-gated by `gag_min_reputation()` = 50, content removers exempt; `messages.gag`); countdown chip in the main banner (`lib/zmanim.ts`, client only; edit TARGETS).
- "עוד" (`pages/FunPage.tsx`, /more; reached only from an unlabeled icon in the top bar, never a sidebar label, to keep the site looking professional; `lib/useMoreNews.ts` shows a dot and a one-time notice on entry when there is a new confession / quote since this browser last looked): anonymous confessions (`confessions`, author in `anon_authors` kind 'confession', follows `can_send_anonymous`; fixed reactions + named comments) and "who said it?" (`quote_quizzes` / `quiz_guesses`, functions only so the answer stays hidden: `grab_quote` from a message's ⋮ menu, never anonymous/system/own lines; `guess_quote`, `quiz_list`, `quiz_leaderboard` = 10 points per correct guess).
- Events calendar: `pages/EventsPage.tsx` (/events), table `events`, functions `add_event` / `update_event` / `delete_event` / `resolve_event`; `event_conflict()` flags a same-name-other-date or similar-name-same-date event as 'conflict' for its original author or admins to settle. Room `channels.purpose = 'blessings'` (created by schema.sql) lets a blessing be scheduled into the calendar (`events.message_id`).
- Installable app + push: `public/manifest.webmanifest`, `public/sw.js` (shows pushes, opens the chat on click), `lib/push.ts`, `components/PushSettings.tsx`. Edge Function `supabase/functions/send-push` (web-push; creates VAPID keys in `push_config` on first run; also runs `send_due_scheduled()`), woken by `push_kick()` via pg_net after a message and every minute by pg_cron. `queue_push()` is fed by the same triggers as email (DMs, mentions, replies, polls, requests), per-member `push_prefs`, devices in `push_subscriptions`.
- Message actions: forward (`ForwardDialog`), mark unread (`mark_room_unread` / `mark_dm_unread`), star (`stars` table, `/starred`), pin to room board (`set_message_pinned`), copy link (`?m=<id>` deep link), copy text, edit, delete.
- Media: private Storage bucket `media` (created by schema.sql). Chat files `m/<uuid>.<ext>`, profile photos `a/<uuid>.jpg`, profile backgrounds `c/<uuid>.jpg` (3:1, `profiles.cover_path`); names never contain the uploader (anonymity). `lib/media.ts` shrinks photos (1600px JPEG), limits video to 20MB / 90s, and serves files through batched signed URLs.
- Realtime: postgres_changes via `subscribe()` in `src/lib/realtime.ts` (unique topic per subscription); shared topics (presence, typing) via `joinShared()`. Reusing a topic while the old channel is being removed throws and used to blank the app.
- Backend: Supabase only (Postgres + Auth + Realtime). No custom server. Supabase auth uses PKCE (`src/supabase.ts`) because the hash belongs to the router.
- All authorization lives in `supabase/schema.sql` (RLS policies + guard triggers + SECURITY DEFINER functions). The UI just hides buttons; never rely on it for security.
- Content creation goes through RPCs (`send_message`, `create_room`, `post_wall`, `start_dm`, `send_dm`, `toggle_dm_reaction`); direct inserts are not allowed (room `reactions` and `stars` are plain RLS inserts). Sidebar data: `my_rooms()`, `my_conversations()`.
- Anonymity: anonymous rows have `author_id`/`sender_id` NULL. The real author sits in `anon_authors` (readable only by that author) or `dm_participants.hidden`. Reputation comes only from `message_likes` (a plain like, rooms only, not on your own message) + message count; emoji `reactions` are expression only. Anonymous content never counts toward reputation (it would leak identity). DM reactions by the hidden side store user_id NULL. Keep it that way.
- Roles: member, inspector ("מפקח": may delete any room message, wall post or file via `can_remove_content()`), admin, plus the owner ("מנהל-על"): the account whose email is `owner_email()` in schema.sql (= `OWNER_EMAIL` in `src/supabase.ts`; login alias `shmuel`). The owner is always an active admin nobody can demote or ban, and is the ONLY one whose RLS (`is_owner()`) reveals `anon_authors` and all `dm_*` rows; regular admins/inspectors never see them. Members are told this at sign-up, in TermsGate and next to the anonymous toggle (emergencies only). The legacy `moderator` role still exists but is no longer offered.
- Reset: `reset_everything(p_password)` (owner, or an admin while no owner account exists) checks the caller's own login password against `auth.users.encrypted_password` (no password in code), wipes all content, lists and accounts, and leaves an empty main room; `components/OwnerTools.tsx` empties the Storage bucket first.
- Who may send / receive anonymously is decided by admins only (`profiles.can_send_anonymous`, `accept_anonymous`); enforced in the RPCs on every message.
- Joining: new sign-ups are `pending` until an admin approves, except emails in `preapproved_emails` (admin tab "אישור מראש", RPC `add_preapproved`), which become active on sign-up, and names on the yeshiva `roster` (same tab, RPC `add_roster`; written surname first; matched by `name_tokens()`/`roster_match()`: any word order, hyphen = space, ו/י dropped after a word's first letter, surname required, each roster row claimed once). Roster joins get `profiles.joined_via = 'roster'`, `join_seen = false`, so admins see them in the sidebar / members tab and get a desktop notification. Nobody is ever emailed. Never commit member names or emails to the repo (it is public). Every member must accept the NetFree content rules once (`profiles.terms_accepted_at`, set only by himself, never cleared); `pages/TermsGate.tsx` blocks the app until then.
- Global state (session, own profile, all profiles, channels, presence) in `src/AppContext.tsx`.
- Deploy: `.github/workflows/deploy.yml` builds on push to `main`. Supabase URL + publishable key live in `.env.production` (public by design); optional repo Variable `VITE_SITE_NAME`. Never commit the `sb_secret_` key.

## Checks before pushing
- `npm run build` (typecheck + bundle)
- `supabase/tests/run.sh` against a local Postgres 16 (mocks Supabase `auth` schema): permission tests on a fresh install plus upgrade tests from `tests/fixtures/schema_v1.sql`, `schema_v2.sql`, `schema_v3.sql`, `schema_v4.sql`, `schema_v5.sql`, `schema_v6.sql`, `schema_v7.sql`, `schema_v8.sql`, `schema_v9.sql`, `schema_v10.sql`, `schema_v11.sql`, `schema_v12.sql` and `schema_v13.sql`. Add a test for any policy/trigger change; when making a breaking schema change, snapshot the current schema as the next fixture.
- `schema.sql` must stay idempotent (safe to re-run on the live project).
