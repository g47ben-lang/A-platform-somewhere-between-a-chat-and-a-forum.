# 💬 הקהילה: בין צ'אט לפורום

אתר קהילה סגור לכמה מאות חברים. הוא בנוי בשלוש שכבות:

**ערוצים** ← **נושאים** (כותרת והודעת פתיחה, כמו בפורום) ← **שיחה חיה** בתוך כל נושא (כמו בצ'אט).

## מה יש באתר

- הרשמה עם אימייל וסיסמה. **כל חבר חדש ממתין לאישור מנהל**, כך שהקהילה נשארת סגורה.
- **המשתמש הראשון שנרשם הופך אוטומטית למנהל.**
- הודעות מופיעות בזמן אמת, בלי לרענן את הדף.
- תשובה לציטוט, תגובות אימוג'י, עריכה ומחיקה של הודעות.
- סימון נושאים שיש בהם הודעות שעוד לא נקראו.
- רואים מי מחובר עכשיו.
- חיפוש בנושאים ובהודעות.
- ערוצי "הודעות" שרק מנהלים ומנחים יכולים לפתוח בהם נושאים.
- **הרשאות:** חבר/ה, מנחה (נעיצה, נעילה, העברה ומחיקה), מנהל/ת (אישור חברים, חסימה, מינויים וניהול ערוצים).
- מותאם לטלפון, בעברית מימין לשמאל, עם מצב כהה אוטומטי.

## הטכנולוגיה

| חלק | מה | עלות |
|---|---|---|
| מסד נתונים, משתמשים, זמן אמת | [Supabase](https://supabase.com) | חינם עד 200 חיבורים בו-זמנית ו-500MB. מעבר לזה, Pro ב-25$ לחודש |
| האתר עצמו | React + Vite ב-GitHub Pages | חינם |

כל ההרשאות נאכפות **במסד הנתונים** (Row Level Security), ולא רק בממשק. הן מכוסות בבדיקות אוטומטיות: `supabase/tests/`.

## הקמה: פעם אחת, בערך 15 דקות

### 1. יצירת פרויקט ב-Supabase
1. נכנסים ל-https://supabase.com, נרשמים ולוחצים **New project**.
2. בוחרים אזור **Frankfurt (eu-central-1)**, הקרוב ביותר לישראל. שומרים את סיסמת מסד הנתונים במקום בטוח.

### 2. הקמת מסד הנתונים
1. בתפריט הצד: **SQL Editor** ← **New query**.
2. מדביקים את **כל** התוכן של הקובץ [`supabase/schema.sql`](supabase/schema.sql) ולוחצים **Run**.

### 3. הגדרות התחברות
ב-**Authentication**:
- **Sign In / Providers ← Email:** מומלץ לכבות את **Confirm email**. שירות המייל המובנה של Supabase מוגבל לכמה מיילים בשעה, וכשכמה עשרות אנשים נרשמים בבת אחת זה נתקע. גם בלי אימות מייל, אף אחד לא נכנס בלי אישור מנהל.
  - אם רוצים אימות מייל ואיפוס סיסמה במייל, צריך לחבר שירות SMTP. [Resend](https://resend.com) חינמי עד 3,000 מיילים בחודש. מגדירים אותו ב-**Authentication ← Emails ← SMTP Settings**.
- **URL Configuration:** ב-**Site URL** שמים את כתובת האתר (שלב 5). את אותה כתובת מוסיפים גם ל-**Redirect URLs**.

### 4. חיבור GitHub ל-Supabase
1. ב-Supabase: **Project Settings ← API**. מעתיקים את **Project URL** ואת **anon / publishable key**. המפתח הזה ציבורי מטבעו, ומותר שיופיע באתר.
2. ב-GitHub, בדף הריפו: **Settings ← Secrets and variables ← Actions ← לשונית Variables ← New repository variable**. יוצרים:
   - `VITE_SUPABASE_URL` עם ה-Project URL
   - `VITE_SUPABASE_ANON_KEY` עם המפתח
   - `VITE_SITE_NAME` (לא חובה) עם שם הקהילה שיוצג באתר

### 5. העלאת האתר לאוויר
1. ב-GitHub: **Settings ← Pages ← Source: GitHub Actions**.
2. כל עדכון שנכנס לענף `main` מעלה את האתר אוטומטית. אפשר גם להפעיל ידנית: **Actions ← Deploy to GitHub Pages ← Run workflow**.
3. כתובת האתר תהיה בערך כך: `https://g47ben-lang.github.io/<שם-הריפו>/`

### 6. כניסה ראשונה
נכנסים לאתר ונרשמים. **המשתמש הראשון הופך למנהל.** אחר כך שולחים את הקישור לחברי הקהילה, ומאשרים אותם בדף **⚙️ ניהול**. יש שם גם כפתור "אישור כולם".

## פיתוח מקומי

```bash
cp .env.example .env.local   # ממלאים את הערכים מ-Supabase
npm install
npm run dev
```

בדיקות הרשאות מול Postgres מקומי:
```bash
PGHOST=localhost PGUSER=postgres supabase/tests/run.sh
```

## שינויים במסד הנתונים בעתיד
את `schema.sql` אפשר להריץ שוב בבטחה, והוא לא מוחק נתונים. בשינויים גדולים יותר מוסיפים קובץ מיגרציה חדש לתיקייה `supabase/`.
